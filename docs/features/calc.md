# 计算引擎

::: tip 适用形态
WPS JS 加载项 4.67 ✅ ｜ Excel VBA 4.66 ✅（VBA 版为 `Clean_Math_Expression` + `Application.Evaluate`）
:::

## 它解决什么问题

造价底稿里的算式不是标准公式：混着中文材料名、【】、全角括号、百分号，甚至用 `##` 做跳过标记。
计算引擎先把这些干扰清洗掉，再用自研求值器计算——**不依赖宿主求值**（WPS 加载项宿主未必提供 `Application.Evaluate`），因此同一套逻辑能在 Node 里被完整测试。

## 它被谁使用

| 使用方 | 用途 |
| --- | --- |
| [`=Z.JS()`](/features/custom-function.html) | 单元格函数求值 |
| 审计时间线 / 差异比对 | 计算"原值算量 / 新值算量 / 变化量" |
| 沉浸阅读 | 悬停显示局部算量、顶部结果 |
| 统计大屏 | 汇总核增/核减金额 |

## 支持的语法

| 能力 | 示例 | 结果 |
| --- | --- | --- |
| 四则运算 | `3.5*(2+1)` | 10.5 |
| 一元正负 | `-3+5` | 2 |
| 幂（左结合） | `2^3^2` | 64 |
| 百分号 | `200*10%` | 20 |
| 嵌套括号（含全角） | `（（1+2）*3）` | 9 |
| 中文/【】清洗 | `钢筋 5.5*2` | 11 |
| 跳过标记 | `##这段不参与` | 被清除 |

## 清洗规则（与 VBA 对齐）

1. 剥离变色跳过标记（默认 `##`）之后的内容；
2. 去【】、中文、字母等非数学字符——**替换为空格**，让 `3 *4 1` 这类错误暴露出来，而不是悄悄算对；
3. 全角括号转半角；
4. 清除换行；
5. 去掉首尾多余的 `*` `/`；
6. 交给求值器。

## 操作与调用

**普通用户**：不需要单独操作，`=Z.JS()`、时间线、阅读面板会自动使用。

**开发者**：

```js
ZSMD.Calc.JS("3.5*(2+1)-【损耗】5%")   // 10.45
ZSMD.Calc.cleanMathExpression("【x】 5+2") // "5+2"（只清洗不求值）
```

## 参数与开关

| 名称 | 默认 | 说明 |
| --- | --- | --- |
| 变色跳过标记 | `##` | 清洗时在该标记处截断 |
| 幂运算方向 | 左结合 | 对齐 Excel/VBA 的 `^` |
| 精度 | JS Number | 展示层做两位小数舍入；比较时按原始数值 |

## 结果与判定

- `3.5*(2+1)-【损耗】5%` 返回 `10.45` → 清洗与求值都正确；
- 非法算式返回 `#错误:[清洗后文本]`，不弹窗、不抛异常 → 容错生效；
- 同一算式在单元格 `=Z.JS()`、阅读面板、时间线里结果一致 → 引擎统一。

## 边界与注意事项

- 引擎只做**四则/幂/百分号**，不支持函数、变量、名称引用；单元格引用由 `=Z.JS(A1)` 外层解包后传入（见[单元格函数](/features/custom-function.html)）；
- 浮点精度遵循 IEEE 754，金额比较请用两位小数口径；
- 除零等非法运算返回 `#错误:` 文本，不会中断流程；
- 清洗是"破坏性"的：中文被替换为空格，所以 `【损耗】5%` 才能被当作 `5%` 计算，但也意味着中文不能参与运算语义。
