# 差异比对与恢复

::: tip 适用形态
WPS JS 加载项 4.67 ✅ ｜ Excel VBA 4.66 ✅（差异见[双实现能力矩阵](/dev/parity.html)）
:::

## 它解决什么问题

审计时间线告诉你"改过几次"，差异比对告诉你"每次改在哪几个字符"。
长算式里改一个系数、删一个括号，肉眼很难发现；差异比对会把旧值和新值**逐字符对照**（技术名 LCS），删除标红、增加标绿，并同时给出**算量变化量**（改前算量 → 改后算量 → 净变化）。

## 它出现在哪

| 位置 | 展示内容 |
| --- | --- |
| 审计面板 · 全局总览 | 最终版 vs 基准点：原算量 / 新算量 / 变化量 + 红绿行 |
| 审计面板 · 历史节点 | 每个节点的修改人、时间、算量变化量、红绿差异 |
| 审计面板 · 基准点卡片 | 未审计前原值 |
| 沉浸阅读 · 历史快照 | 某一版算式的结构化阅读视图（标记"历史版本快照"） |

## 操作步骤

1. 先让目标单元格产生审计记录（见[实时审计与时间线](/features/audit.html)）；
2. 选中该单元格 →「视图与审查 → 审计面板」；
3. 在时间线中查看：
   - 顶部「全局总览」看最终相对基准点的净变化；
   - 中间每个节点看单次改动；
   - 底部「基准点」看最初的值；
4. 需要对某一版做操作时：
   - **解析**：按该节点的**新值**重新解析算量（不改变单元格）；
   - **恢复**：把该节点的**新值**写回当前单元格（写操作，会产生新审计记录）。

::: warning 「解析/恢复」作用于节点的新值
这是与 VBA 版一致的行为：点历史节点上的按钮，处理的是那一版提交后的值，而不是基准点。
:::

## 参数与开关

| 名称 | 默认 | 说明 |
| --- | --- | --- |
| 保留最近批注数 | 5 | 决定时间线上最多能回溯几个节点；0 不限制 |
| 审计范围(Audit) | 按表生成 | 决定哪些单元格会进入时间线 |
| 审计背景颜色 | `#87CEEB` | 有记录的单元格底色，便于定位 |
| 计算清洗规则 | 跳过标记 `##` | 算量解析复用[计算引擎](/features/calc.html)的清洗逻辑 |

## 结果与判定

- 删除内容显示为红色删除线/红底，新增内容显示为绿色 → LCS 生效；
- 「算量变化量」为两位小数，与手工按计算器结果一致 → 解析正确；
- 节点顺序与修改时间一致，基准点固定不变 → 时间线正确。

## 边界与注意事项

- **字符级比对基于文本**：改的是公式文本还是数值，展示方式不同；数值变化由"算量变化量"单独给出；
- 长文本（上千字符）的 LCS 计算量较大，面板会慢一些，属正常；
- 差异结果是 HTML 片段，已做转义，算式里的 `<`、`&` 不会破坏渲染；
- 「恢复」是写操作且不可撤销（会继续追加审计记录），执行前确认；
- 若批注被手工清空，时间线随之消失（批注即历史）。
