# 实时审计与时间线

::: tip 适用形态
WPS JS 加载项 4.67 ✅ ｜ Excel VBA 4.66 ✅（差异见[双实现能力矩阵](/dev/parity.html)）
:::

## 它解决什么问题

结算审计里最难还原的不是结果，而是**过程**：这个量是谁改的、什么时候改的、改前是多少、为什么改。
智算墨斗把每次单元格改动写进批注，形成可回溯的审计链；复核时不用翻聊天记录、不用问同事，打开时间线就能看到完整演变。

## 触发链路（什么时候才会记录）

一次单元格改动进入审计，要依次通过以下判定（与源码 `js/core/events.js` 一致）：

| 顺序 | 判定 | 不满足时 |
| --- | --- | --- |
| 1 | 工作簿已「启用」 | 忽略 |
| 2 | 不是系统表（`Admin_Config` / `Log_Audit` / `Vault_*`） | 忽略 |
| 3 | 目标表未开启隐私模式 | 撤销本次改动（隐私表只允许解密后编辑） |
| 4 | 单次改动 ≤ 5000 个单元格 | 跳过并提示"超大批量修改" |
| 5 | 全局审计 + 该表「是否开启审计」都开启 | 忽略 |
| 6 | 改动落在该表「审计范围(Audit)」列指定的区域 | 忽略 |

> 配置表修改会走单独分支：系统内部写入不拦截，用户手改受保护开关会被拦回并重载配置。

## 审计链长什么样

每个被审计的单元格批注都按固定结构写入：

```text
【未审计前原值】: 34.49
=================================

--- 修改于 2026-03-27 11:14:16
修改人: <当前用户名>
原值: 34.49
新值: 33.29
--- 用户批注 ---
（可选的人工说明）
```

三条关键规则：

1. **基准点永不丢失**：`【未审计前原值】` 与分隔行不受"保留最近 N 条"影响，也不会被后续值覆盖；
2. **保留最近 N 条**：默认 5 条，可在配置表「保留最近批注数」调整；0 表示不限制；
3. **用户批注保留**：`--- 用户批注 ---` 之后的手工内容不会被截断或覆盖。

## 操作步骤

1. 确认工作簿已启用、全局审计开启、目标表「是否开启审计」为开启；
2. 正常修改单元格（单格或小范围区域）；
3. 选中被改过的单元格 →「视图与审查 → 审计面板」；
4. 在面板里查看：全局总览（最终值 vs 基准点）、每个历史节点、基准点原值；
5. 需要时使用节点上的「解析」（按该节点的算式解析算量）与「恢复」（把该节点的新值写回）。

::: warning 恢复是写操作
「恢复」会把历史节点的新值写回当前单元格，并继续产生新的审计记录；确认无误再点。
:::

## 参数与开关

| 名称 | 默认 | 作用 | 何时修改 |
| --- | --- | --- | --- |
| 全局审计总开关 | 开启 | 整个工作簿是否记录审计 | 临时性能优化时关闭 |
| 是否开启审计（按表） | 生成时自动 | 单表是否记录 | 只审需要复核的表 |
| 审计范围(Audit) | 按表生成 | 限定参与审计的列/区域 | 大表缩小范围可显著提速 |
| 保留最近批注数 | 5 | 每格最多保留几条历史 | 需要完整过程时调大或设 0 |
| 审计背景颜色 | `#87CEEB` | 有审计记录单元格的底色 | 与项目模板配色冲突时改 |
| 撤销 / 重做 | — | 保存最近若干步改动（撤销/重做栈） | Ribbon「撤销」「重做」 |

## 结果与判定

- 改完单元格后，批注里出现 `--- 修改于` 记录，且单元格底色变化 → 成功；
- 面板时间线节点数与实际修改次数一致（受"保留最近 N 条"限制）→ 成功；
- 基准点始终是最早的未审计值，不随修改变化 → 可放心用于核增/核减计算。

## 边界与注意事项

- **超大批量会跳过**：一次改动超过 5000 单元格（如整列粘贴）不记录，避免卡死；
- **隐私表不可直接编辑**：在隐私模式下改单元格会被撤销，需先「密码解密」；
- **只读/受保护/共享工作簿**可能不触发事件，审计会缺失；
- **事件被禁用**（宏安全、平台限制）时无记录，属环境问题；
- 批注是审计链载体：**删除批注 = 删除该格历史**，操作前先导出或备份。
