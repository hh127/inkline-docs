# 配置表开关锁定

## 症状

- 用户直接在 `Admin_Config` 里把「全局审计总开关」改成关闭，保存后又被改回"开启"；
- 或者相反：用户改了开关，程序读到的却不是用户写的值，拦截逻辑失效。

## 根因

全局开关必须**系统独占**：审计/变色被误关会让用户以为功能坏了，排查成本极高。所以这 5 个键被标记为锁定：

| 锁定键 |
| --- |
| `是否启用智算墨斗` |
| `全局变色总开关` |
| `全局审计总开关` |
| `显示看历史悬浮按钮` |
| `显示阅读模式悬浮按钮` |

只靠工作表保护（Protect）不够——宿主在部分场景仍可能写入，且加载项未必能可靠控制 `EnableEvents`。所以需要**双保险**：

1. 工作表 Protect；
2. `SheetChange` 事件里拦截对锁定键的写入，恢复系统值。

而"脏值"坑出在事件顺序上：

> 事件触发时，单元格里已经是用户刚写的值。如果先 `reload` 配置再判断，会把**用户刚写的脏值**读进内存当作"系统真值"，
> 后续比对基准就错了——拦截等于没拦。

## 方案

- 锁定键清单由 `config.js` 维护（`LOCKED` 数组），与保护/拦截共用一份；
- 事件分支顺序调整为：**先判断是否系统内部写入**（`isSystemWriting` 标记）→ 再执行锁定校验（`enforceProtectedSwitch`）→ 最后才 `reload`；
- 系统内部写入（开关回写、配置生成、注册表同步）直接 `return`，不允许被拦截，否则系统写入会被回滚；
- 切换开关走 Ribbon 按钮/侧边栏，由程序写入并打标。

## 验证

| 用例 | 期望 |
| --- | --- |
| 手动改锁定键 → 保存 | 被恢复为系统值，配置重载 |
| 点 Ribbon 开关 | 正常切换，不被拦截 |
| 生成/重载配置表 | 系统写入不触发拦截、不回滚 |
| 自动化 | `test/config-lock.test.js`、`test/master-switch.test.js` 覆盖 |

## 你也遇到了？

- ☐ 手改的是不是这 5 个锁定键之一（其他参数允许手改）
- ☐ 是否在改完后又触发了别的宏/插件写入
- ☐ 是否自己关过 `EnableEvents` 没恢复
- ☐ 参考[配置表与控制台](/guide/settings.html)「锁定规则」
