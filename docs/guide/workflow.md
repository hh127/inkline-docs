# 典型工作流

下面三条流程覆盖软件的主要使用场景。每条都给出「做什么 → 用哪个功能 → 产出什么」，方便照着排自己的作业顺序。

## 流程一：算量核对（读算式）

**目标**：确认工程量计算式与结果一致，快速找出括号/口径错误。

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 生成配置表，对目标表开启「是否开启变色」 | 算式按括号层级着色 |
| 2 | 逐条阅读算式；复杂式用「沉浸阅读」展开结构 | 结构化的算式视图（胶囊/注释透视） |
| 3 | 对可疑单元格用 `=Z.JS()` 独立复算 | 与表内结果对照的独立值 |
| 4 | 需要留痕时开启审计，再做修改 | 审计链 + 时间线 |

**要点**：变色只是"显示辅助"，不改公式；`=Z.JS()` 复算与表内公式是两条独立路径，结果不一致就是排查入口。

见[变色与括号层级](/features/highlight.html)、[沉浸阅读](/features/reading.html)、[单元格函数](/features/custom-function.html)。

## 流程二：结算审计（留痕与追溯）

**目标**：审计期间的每次调整都可追溯，能回答"谁在什么时候把量改成了多少、为什么"。

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 生成配置表并「启用」当前工作簿 | 事件桥工作 |
| 2 | 打开全局审计 + 目标表「是否开启审计」，设好审计范围 | 审计开始 |
| 3 | 正常修改（单格/小区域），必要时在批注里写「用户批注」 | 每格审计链 |
| 4 | 复核时打开「审计面板」看时间线 | 全局总览 + 节点 + 基准点 |
| 5 | 对争议节点用「解析」看算量、用「恢复」回到某状态 | 可解释的调整过程 |
| 6 | 阶段性用「统计大屏」看偏离度、修改次数、作者画像 | 项目审计画像 |

**要点**：

- 批量粘贴超过 5000 单元格会跳过自动处理，审计调整尽量单格/小区域；
- 「恢复」是写操作，会产生新记录；
- 审计链存在批注里，**删批注 = 删历史**，交接前先备份。

见[实时审计与时间线](/features/audit.html)、[差异比对](/features/diff.html)、[统计大屏](/features/dashboard.html)。

## 流程三：复核与交付（安全与归档）

**目标**：把成果安全地交给下一方，同时不泄露敏感信息、不把内部审计痕迹带出去。

| 步骤 | 操作 | 产出 |
| --- | --- | --- |
| 1 | 用「导出审查版」生成内部复核副本 | 含审计痕迹的副本 |
| 2 | 用「导出外部交付版」生成清洁副本（清洗公式/痕迹） | 对外交付文件 |
| 3 | 交付前对敏感表做「隐私加密」并发密码 | `Vault_` 金库 + 掩码 |
| 4 | 确认无需保留历史后，用「清除审计标记」清掉机器批注 | 干净底稿 |
| 5 | 归档：项目文件 + 导出副本 + 密码记录（分开存放） | 可追溯的交付包 |

**要点**：

- 导出采用「副本另存 → 打开副本 → 清洗 → 另存」路径，**原表零改动**；
- 隐私加密不是强加密，敏感程度高的文件请叠加文件级加密/加密盘；
- 「清除审计标记」不可撤销，执行前先导出审查版。

见[导出审查版/交付版](/features/export.html)、[隐私模式与金库](/features/privacy.html)、[清除审计标记](/features/audit-tools.html)。

## 角色建议

| 角色 | 主要操作 | 建议权限 |
| --- | --- | --- |
| 造价/预算员 | 算量、变色、`=Z.JS()` 复算 | 编辑权，审计可开可关 |
| 主审/复核 | 审计链、时间线、统计大屏 | 审计常开，导出审查版 |
| 交付/商务 | 隐私加密、导出交付版、归档 | 只读 + 导出 |
| 管理员 | 部署、升级、排障 | 服务端与 `publish.xml` |

## 交接清单（建议写进项目 SOP）

- [ ] 交付前已导出审查版并留存
- [ ] 交付版已清洗，且抽查无审计批注残留
- [ ] 隐私表密码已通过独立渠道传递
- [ ] 配置表里的项目名称/主审人已填写（大屏展示用）
- [ ] 归档包含：项目文件、审查版、交付版、密码记录、版本号（4.67.0）
