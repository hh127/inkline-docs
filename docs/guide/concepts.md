# 核心概念

先花 5 分钟建立这几个概念，后面所有功能页都会用到。

## 工作簿里多了什么

「生成配置表」之后，工作簿里会出现三类系统表：

| 工作表 | 作用 | 谁来维护 |
| --- | --- | --- |
| `Admin_Config` | 配置表：全局参数 + 每张表的开关与范围 | 软件生成；按钮/面板修改 |
| `Log_Audit` | 审计流水（可选的集中记录） | 软件 |
| `Vault_<表名>` | 隐私模式下存放原表副本的隐藏金库 | 软件，仅在加密时出现 |

::: danger 不要手改系统表
系统表由事件层保护：手改全局开关会被拦回原值，误删会导致功能失效。改配置请用按钮或侧边栏面板。
:::

## 配置表长什么样

`Admin_Config` 分两块：

**① 全局参数区**（键 / 值 / 说明三列，部分参数带颜色盒）——控制整个工作簿的行为，例如「是否启用智算墨斗」「全局变色总开关」「保留最近批注数」。

**② 工作表清单区**——每张表一行：

| 列 | 含义 |
| --- | --- |
| 工作表名称 | 表名 |
| 审计范围(Audit) | 哪些列/区域参与审计记录 |
| 变色范围(Color) | 哪些列/区域参与变色 |
| 是否开启审计 | 该表是否记录审计 |
| 是否开启变色 | 该表是否自动变色 |
| 隐私遮蔽模式 | 该表是否处于隐私加密状态 |

**新加的工作表默认不开启**，需要在配置表里打开对应开关——这是新人最常问的问题。

## 审计链与基准点

一次单元格改动会写入批注，形成审计链：

```text
【未审计前原值】: 34.49        ← 基准点（永不丢失）
=================================
--- 修改于 2026-03-27 11:14:16
修改人: <用户名>
原值: 34.49
新值: 33.29
--- 用户批注 ---               ← 手工内容，不会被覆盖
```

- **基准点**：最早的未审计值，用于计算核增/核减，永远保留；
- **保留最近批注数**：默认 5 条，超过后只截断历史节点，不截断基准点与用户批注；
- **时间线面板**：把批注解析成可视化节点（修改人、时间、算量变化量、红绿差异）。

细节见[实时审计与时间线](/features/audit.html)。

## 变色与括号层级

变色只改**显示样式**，不改值与公式。括号按嵌套层级着色，默认 5 层：蓝 → 绿 → 橙 → 紫 → 深红，超过 5 层循环回第 1 层；中文与数字用高亮色；含跳过标记（默认 `##`）的整格跳过。

细节见[变色与括号层级](/features/highlight.html)。

## 隐私金库（务必理解它的边界）

「隐私加密」并不是密码学加密，而是三步：

1. 把当前表复制到隐藏工作表 `Vault_<表名>`（`VeryHidden`）；
2. 原表内容用 `******` 掩码覆盖；
3. 给工作表加保护密码。

因此它**防的是"误看"和"随手转发"**，不能抵御专业工具还原。需要强加密请使用文件级加密（如带密码的压缩包/加密盘）。
细节与操作见[隐私模式与金库](/features/privacy.html)。

## 双形态与版本口径

| | WPS JS 4.67 | Excel VBA 4.66 |
| --- | --- | --- |
| 状态 | **当前主线** | 冻结基线 |
| 获取方式 | 源码部署（无 4.67 安装包） | `releases/` 的 xlsm |
| 单元格函数 | `=Z.JS()` | `JS()` UDF |
| 表内悬浮按钮/快捷键 | 有意不做（Ribbon + 侧边栏替代） | 有 |

完整对照见[双实现能力矩阵](/dev/parity.html)与[版本更新](/changelog/)。

## 版本号去哪看

- 源码：`wps-js-plugin/package.json` 的 `version`（当前 4.67.0）
- 站点：首页与[版本更新](/changelog/)页的 `version`
- 制品：`releases/` 只有 4.66 —— 不要用制品版本去推断源码版本
